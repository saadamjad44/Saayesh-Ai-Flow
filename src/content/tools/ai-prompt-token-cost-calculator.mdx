## How token pricing actually works

Every API model is billed by the token, not by the message. A token is a chunk of text — roughly four characters, or three-quarters of a word, for English prose. The word "calculator" is two tokens; "hello" is one; a long compound German word might be several. You pay separately for the tokens you send (input) and the tokens the model sends back (output), and the output rate is always higher — usually three to five times the input rate on the same model.

That matters because the length of the reply drives the bill more than the length of the prompt does. A 200-word prompt that asks for a 50-word reply costs almost nothing, even on an expensive model. The same 200-word prompt that asks for a 2,000-word article can cost twenty times as much on the same model, because the output volume dominates. The second input on the calculator — expected response length — is where that trade-off is visible.

The token counts shown above are estimated from character length. For OpenAI, Claude and Gemini on English prose, that estimate is accurate to within about ten per cent. For code, non-English text, or prompts with lots of punctuation and structure, it can under-count by more. If the exact figure matters, run the prompt once in the vendor's own playground, where the tokeniser is shown.

## The three mistakes that make an AI bill explode

1. **Picking the most expensive model for everything "to be safe".** Most small business work — emails, summaries, draft content, classification — is done well by the cheapest tier. Paying for Opus or GPT-4o on every run of a workflow that GPT-4o mini would have handled is the single most common overpayment pattern.
2. **Forgetting response length matters more than prompt length.** A long system prompt costs one unit of input per run. A long output costs one unit of output per run, at a higher rate. If your prompt says "answer in detail", you have asked for the larger half of the bill.
3. **Not testing the cheapest model first.** The honest workflow is to try the cheapest model that could plausibly work, use it on the task for a week, and only upgrade when you hit a specific limitation. The reverse — starting at the top and never checking downwards — is where quiet overpayment lives.

## How to cut AI costs by 50 to 80 per cent

- **Start at the cheapest tier that could plausibly work.** GPT-4o mini, Gemini 2.5 Flash and Claude Haiku are all under a dollar per million input tokens. Try the task there first, for a week, before considering an upgrade.
- **Batch similar prompts.** If you run the same prompt on ten inputs in a row, most assistants accept all ten in a single call, saving the per-request overhead and often the system prompt tokens.
- **Shorten the output explicitly.** Add "reply in at most 50 words" or "give me the single best option, no alternatives" to the system prompt. The output rate is the higher one; cutting output is the biggest saving per sentence removed.
- **Cache repeated context.** If every run uses the same long document, Anthropic's context caching feature lets you charge for it once and reuse the cached version at a fraction of the rate. The vendor pricing pages explain the discount.
- **Compress prompts.** Remove filler, cut polite preambles, and keep only the instruction and the content. Prompts written like a legal memo cost more than ones written like a direct message, for no quality gain.
- **Move the quality upgrade to the cases that need it.** A workflow does not need to run on one model. Classify with the cheap one, then route the hard cases to the more capable one. The savings on the first step are usually larger than the extra spend on the second.

## About this calculator

It is free, needs no account, and takes no email address. Every price shown is the vendor's public list price on the date at the bottom of the tool; no price is marked up, discounted, or inferred. Token counts are estimates, labelled as such, because this site does not load a multi-megabyte tokeniser bundle for a utility whose purpose is comparison rather than billing.

It does not estimate quality, latency, context window, or fit. Those depend on the specific task, and a calculator that invented those numbers would mislead more than it would help.
